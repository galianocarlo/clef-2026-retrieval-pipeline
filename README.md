### Organisation of the repository ###

The repository is organised as follows:

* `code`: this folder contains the source code of the developed system. See dedicated section below for more details.
* `runs`: this folder contains the runs produced by the developed system.
* `results`: this folder contains the performance scores of the runs.
* `homework-1`: this folder contains the report describing the techniques applied and insights gained.
* `homework-2`: this folder contains the final paper submitted to CLEF.
* `slides`: this folder contains the slides used for presenting the conducted project.

## Organization of the `code` folder

The `code` folder serves as starter for the participation at [CheckThat! 2026](https://checkthat.gitlab.io/clef2026/task1/) at [CLEF 2026](https://clef2026.clef-initiative.eu/).

This section contains a multi-stage search pipeline for scientific papers from tweets:

### pylucene/src/ (The Entry Point)

* **`runner.py`**: It provides a user-friendly menu to execute any version of our pipeline (V1 to V4) across different data splits (`train`, `dev`, `test`). It dynamically manages environment variables for FAISS vector dimensions, safely coordinates index building, executes the search scripts, and can automatically trigger the evaluation script to display the official scores. (python src/runner.py)

* **`load_dataset.py`**: It connects to the HuggingFace repository to fetch the raw CLEF dataset splits (Train, Dev, Test) across all target languages (EN, FR, DE). It automatically formats and saves the data as `.jsonl` files directly into the `experiment/docs/` directory.

### 1. `experiment/runs/` (Output Files)

This directory contains the TREC-formatted results generated by our search engines. Following our methodology, files are dynamically generated based on the architecture version and the evaluated split (e.g., `_train.txt`, `_dev.txt`, `_test.txt`):

* **`run-v1_{split}.txt`**: Results from the Lexical Baseline (V1) using pure PyLucene BM25 with native multilingual analyzers.
* **`run-v2_{split}.txt`**: Results from the Statistical Query Expansion (V2) using BM25 enhanced with Pseudo-Relevance Feedback (PRF).
* **`run-V3_{split}.txt`**: Results from the Hybrid Asymmetric Search (V3). Combines dense retrieval (`e5-base`), BM25, and a Neural Re-ranker using a Max-P chunking strategy for long documents.
* **`run-V4_{split}.txt`**: Results from our SOTA Architecture (V4). Utilizes long-context embeddings (`BAAI/bge-m3`) for full-document dense retrieval, merged with lexical search and Neural Re-ranking, eliminating the need for chunking.

### 2. `pylucene/src/Evaluation/` (Scoring & Merging)

* **`evaluate.py`**: The official evaluation script. It uses the `ranx` library to compute standard IR metrics (MRR@5, MAP, NDCG, Precision, Recall). It calculates exact language-specific scores and computes the final **Macro-Average** required by the Codabench platform.
* **`generate_qrels.py`**: Extracts the ground truth (query-document relevance) from the dataset and formats it into standard TREC `qrels.txt` files required for the `evaluate.py` script.

### 3. `pylucene/src/Index/` (Indexing)

* **`index.py`**: Builds the core PyLucene inverted index, applying native language analyzers and configuring BM25 parameters.
* **`index_faiss.py`**: The hybrid indexer used for V3 and V4. It simultaneously builds the PyLucene index and the FAISS dense vector space. It dynamically adapts its embedding dimension (768d vs 1024d) based on the environment variables for the `runner.py` script.

### 4. `pylucene/src/Parse/` (Data Pre-processing)

* **`parse_documents.py`**: Handles reading, cleaning, and structuring the raw JSONL medical papers into `ParsedDocument` objects ready for indexing.
* **`parse_query.py`**: Processes raw JSONL queries (simulated user tweets or clinical questions), extracting the relevant text and handling specific metadata.

### 5. `pylucene/src/Search/` (Search Engines)

* **`search_v1.py` - `search_v4.py`**: The core execution scripts for each of the four methodologies described in our paper. They handle the query parsing, Lucene/FAISS querying, candidate pooling, and cross-encoder re-ranking.

### 6. `pylucene/src/utils/` (Submission Format)

* **`generate_submission.py`**: the script that convert our TRAC format into TSV format and it zips the solutions.

* **`generate_report.py`**: It scans the `experiment/runs/` directory for all generated outputs, runs `evaluate.py` on each of them, and produces a consolidated `master_metrics_report.txt`. This report includes a sorted leaderboard (based on MRR@5) and detailed per-language breakdowns, providing a clear historical progression of our methodology's performance.
